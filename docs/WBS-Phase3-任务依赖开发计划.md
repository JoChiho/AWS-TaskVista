## 1. 目标与术语

本阶段为 TaskVista 增加“任务依赖（前置／后续关系）”：

```text
A ─┐
   ├──→ C
B ─┘
```

含义：A、B 全部完成后，C 才能开始。

任务依赖与 WBS 父子关系必须保持为两个独立维度：

| 关系 | 表达内容 | 当前／计划字段 |
|---|---|---|
| WBS 父子关系 | 工作由哪些子工作组成，并执行父级汇总 | `parentTaskId` |
| WBS 顺序 | 同一父节点内的显示顺序 | `sortOrder` |
| WBS 编号 | 人可读的结构编号 | `wbsCode` |
| 任务依赖 | 工作必须按照什么顺序发生 | `predecessorIds` |

WBS 父任务的状态、日期、工时和完成率由子任务汇总；任务依赖只控制后续任务是否具备开始条件，不参与父级汇总。

---

## 2. 第一版产品边界

第一版采用以下规则：

1. `predecessorIds` 中的多个前置任务采用 **AND** 关系。
2. 只有 `status === '完了'` 才视为前置条件满足。
3. 依赖关系只允许建立在同一项目内的非删除叶子任务之间。
4. 阻塞是派生状态，不增加新的 `TaskStatus`。
5. 前置任务全部完成后，后续任务只变为“可开始”，不会自动进入 `進行中`。
6. 依赖关系使用稳定的 `taskId` 保存，不使用可能重编号的 `wbsCode`。
7. 第一版不支持 OR 条件、依赖分组、跨项目依赖、自动排程和关键路径。
8. 第一版只支持 Finish-to-Start 语义；SS、FF、SF 和 lag 等高级类型留作后续扩展。

## 3. 数据模型

### 3.1 持久化字段

在前后端 `Task`、创建请求和更新请求中增加：

```ts
predecessorIds?: string[]
```

例如：

```json
{
  "taskId": "C",
  "title": "C任务",
  "predecessorIds": ["A", "B"]
}
```

旧任务缺少该字段时按空数组处理，不需要批量回填。

### 3.2 读取时派生字段

以下字段不持久化，读取项目任务时根据当前任务集合计算：

```ts
type DependencyState = 'ready' | 'blocked' | 'at_risk'

interface TaskDependencyView {
  dependencyState: DependencyState
  blockedByIds: string[]
  successorIds: string[]
}
```

含义：

- `ready`：无前置任务，或所有前置任务均已完成。
- `blocked`：任务尚未开始，且至少一个前置任务未完成。
- `at_risk`：任务已经开始或完成，但已有前置任务被重新打开。

`successorIds` 根据其他任务的 `predecessorIds` 反向计算，不进行双向持久化，避免两份关系数据不一致。

### 3.3 DynamoDB 方针

第一版直接把 `predecessorIds` 保存到现有 Tasks 表的任务 Item 中：

- 不新增依赖表。
- 不新增 GSI。
- 继续利用项目任务列表查询进行图计算。
- 项目规模明显增长、需要跨项目依赖或大量按前置任务反查时，再评估独立关系表。

## 4. 后端业务规则

### 4.1 保存校验

创建或修改依赖关系时必须验证：

1. 当前任务与所有前置任务属于同一项目。
2. 不能依赖自身。
3. 不能依赖逻辑删除任务。
4. 去除重复 ID。
5. 当前任务和前置任务均为叶子任务。
6. 新关系不能产生有向环。
7. 已经开始的任务不能新增尚未完成的前置任务。
8. WBS 循环与依赖循环分别检测，不能复用同一语义判断。

循环示例：

```text
A → B → C
```

此时必须拒绝新增 `C → A`。

建议集中实现以下领域函数：

```text
validateTaskDependencies()
detectDependencyCycle()
deriveDependencyState()
findSuccessorTasks()
```

### 4.2 执行门禁

当任务处于 `blocked` 时：

允许：

- 保持或切换到 `未着手`
- 切换到 `保留`
- 编辑标题、说明、负责人、计划日期和预计工时
- 调整 WBS 位置和排序

禁止：

- 切换到 `進行中`
- 直接切换到 `レビュー待ち` 或 `完了`
- 将完成率设置为大于 0
- 设置实际开始日期
- 设置大于 0 的实际工时

门禁必须在后端统一执行，覆盖：

- `POST /projects/{projectId}/tasks`
- `PUT /tasks/{taskId}`
- `PATCH /tasks/{taskId}/status`

建议错误响应：

```json
{
  "code": "TASK_DEPENDENCY_BLOCKED",
  "message": "前提タスクが完了していないため、このタスクを開始できません。",
  "blockedBy": [
    {
      "taskId": "B",
      "wbsCode": "2",
      "title": "B任务",
      "status": "進行中"
    }
  ]
}
```

### 4.3 前置任务重新打开

依赖采用“开始门禁”语义：

- 后续任务尚未开始：重新进入 `blocked`。
- 后续任务已经开始或完成：不自动回滚状态，标记为 `at_risk`。
- 页面提示“开始后，前置任务被重新打开”，由负责人决定是否设为保留。

不得自动清空实际日期、实际工时或完成率。

### 4.4 删除保护

依赖关系可能跨 WBS 分支，删除不能静默解除依赖：

- 如果任务被子树外的未删除任务依赖，默认阻止删除。
- 删除确认画面列出受影响的后续任务。
- 用户先解除依赖关系，再执行删除。
- 若前置和后续任务都位于同一个被删除子树内，可以随子树一起删除。
- 删除父任务时必须检查其全部后代是否被子树外任务依赖。

### 4.5 API 方针

第一版可通过现有创建和更新 API 保存 `predecessorIds`。

未来在甘特图或构成图提供直接连线编辑时，可增加：

```http
PUT /tasks/{taskId}/dependencies
```

```json
{
  "predecessorIds": ["A", "B"]
}
```

## 5. 任务表单、详情和 Kanban

### 5.1 任务表单

在 WBS 父任务选择区域之后增加独立的依赖区域，避免用户混淆结构与顺序。

建议日语文案：

- 区域标题：`依存関係`
- 字段标题：`前提タスク`
- 帮助文字：`選択したタスクがすべて「完了」になるまで、このタスクは開始できません。`
- 已解除：`着手可能`
- 阻塞中：`前提タスク 1 件が未完了`
- 循环错误：`循環する依存関係は設定できません。`

多选候选显示：

```text
1.1 要件整理      完了
1.2 API設計       進行中
2.1 画面設計      未着手
```

排除当前任务、删除任务、父任务和明确会形成循环的候选项。

### 5.2 任务详情

增加可点击的两个区域：

```text
前提タスク
├─ 1.1 A任务    完了
└─ 2.1 B任务    進行中

後続タスク
└─ 3.1 C任务    未着手
```

阻塞时在详情顶部显示：

```text
前提タスクが未完了のため、まだ開始できません。
```

### 5.3 Kanban

阻塞任务仍显示在 `未着手` 列：

- 显示锁图标。
- 显示 `前提 1件未完了` 标签。
- 悬停显示未完成前置任务。
- 禁止拖入 `進行中`、`レビュー待ち` 和 `完了`。
- 尝试拖动时恢复原位置并显示后端返回的具体原因。

不得自动把阻塞任务移动到 `保留`，因为 `保留` 是用户主动设置的业务状态。

## 6. 甘特图表现

### 6.1 基本表现

在现有甘特时间轴上增加 SVG 依赖线覆盖层：

```text
A  ███████──┐
            ├────▶ █████ C
B    █████──┘
```

- 箭头从前置任务计划条右端出发。
- 箭头指向后续任务计划条左端。
- 使用折线或直角线。
- WBS 父子线和依赖线使用完全不同的颜色与线型。

### 6.2 颜色规则

| 状态 | 依赖线 |
|---|---|
| 前置任务已完成 | 低饱和绿色实线 |
| 等待前置任务 | 橙色实线 |
| 计划日期冲突 | 红色虚线 |
| 当前选中任务相关 | 加粗高亮 |
| 无关关系 | 降低透明度 |

### 6.3 计划冲突

Finish-to-Start 的计划冲突定义为：

```text
后续任务 plannedStartDate
早于
所有前置任务最晚 plannedDueDate 的下一个工作日
```

第一版只提示冲突，不自动重新排期。可以提供：

```text
前提タスク完了後に移動
```

用户确认后，再将后续任务移动到可行的最早工作日。

### 6.4 交互

- 增加 `依存関係を表示` 开关。
- 点击任务后强调其直接前置和后续关系。
- 悬停依赖线时显示 `A → C`。
- 无计划日期的任务只显示依赖标签，不绘制时间轴箭头。
- WBS 折叠隐藏关联任务时，在折叠父行显示依赖数量提示。
- 第一版不支持在甘特条之间直接拖线创建关系。

## 7. 构成图表现

WBS 结构线和任务依赖线必须视觉分离：

| 图形 | 样式 |
|---|---|
| WBS 父子结构 | 灰色或主题色实线，无箭头 |
| 任务依赖 | 蓝色／橙色虚线，带方向箭头 |

节点卡片增加：

```text
┌─────────────────────┐
│ 3.1 C任务      🔒   │
│ 未着手              │
│ 前提 2 · 未完了 1   │
└─────────────────────┘
```

采用焦点模式控制交叉线密度：

1. 默认只显示节点上的前置／后续数量。
2. 用户选择任务后：
   - 前置任务显示蓝色边框。
   - 后续任务显示紫色边框。
   - 无关任务降低透明度。
   - 只绘制与当前任务直接相关的依赖箭头。
3. 可提供“全部显示”，但不作为默认模式。

依赖线可通过构成图画布的 SVG overlay 绘制。WBS 拖拽或重编号后只重新计算卡片坐标，关系本身不变。

第一版只通过任务编辑表单建立关系，不在构成图中通过拖线创建。

## 9. 验收标准

- [ ] A、B 全部完成后 C 才允许开始。
- [ ] A 完成而 B 未完成时 C 仍保持阻塞。
- [ ] 前置任务全部完成后 C 不会自动进入 `進行中`。
- [ ] 禁止自引用、跨项目依赖和依赖删除任务。
- [ ] 禁止 A → B → C → A 循环。
- [ ] WBS 移动和重编号后依赖关系保持不变。
- [ ] 前置任务被外部后续任务依赖时，删除受到保护。
- [ ] Kanban 与任务编辑表单采用相同的后端门禁。
- [ ] 前置任务重新打开时不会强制回滚已开始任务。
- [ ] 甘特图箭头方向、状态颜色和计划冲突提示正确。
- [ ] 构成图的 WBS 实线与依赖虚线不会混淆。
- [ ] 旧任务没有 `predecessorIds` 时行为完全不变。
- [ ] 所有用户可见文案使用自然日语。

## 10. 非目标与后续扩展

以下内容不属于第一版：

- OR 依赖和条件分组。
- Start-to-Start、Finish-to-Finish、Start-to-Finish。
- lag／lead 时间。
- 自动排程与全项目日期联动。
- 关键路径计算。
- 跨项目依赖。
- 甘特图或构成图直接拖线创建依赖。
- 依赖变更审计日志和基线比较。

这些能力应在第一版运行稳定并获得真实使用反馈后再设计。
